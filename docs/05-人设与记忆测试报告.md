## 一、结论摘要

| 能力 | 改前 | 改后 | 判断 |
|---|---|---|---|
| 记住**记忆卡**（notes，逐条事实） | 87.5% | **100%** | 最稳的一路 |
| **群聊身份隔离**（各自报名、互不冒充） | 71.9% | **100%** | 改后满分 |
| 记住**自己名字**（单聊） | 91.7% | 94.4% | 好 |
| 遵守**人设**（职业/年龄/口吻） | 91.7% | 91.7% | 好 |
| 记住**长期记忆**（memory 字段） | 54.2% | **83.3%** | 从缺陷修到可用 |
| 多轮闲聊后**仍记对用户身份** | 50.0% | 66.7% | 仍偏弱 |
| 跨身份**交叉污染**防护 | 62.5% | 56.2% | 仍是短板 |

**总体：76.2% → 88.7%（168 次/版本，42 条用例 × 4 轮），用例全对从 26/42 升到 34/42。**

一句话结论：「记住关于别人的事实」本来就做得好；**真正坏掉的是「分清『我』和『你』」**——用户问「我是谁」，模型答的是自己的名字。这不是记忆问题，是指代问题，**改代码能修**：把问句里的「我」在发送前换成「用户」，四个原本 0/4 的崩溃点全部变成 4/4。

**但这四轮迭代的更大收获是负结果**：任何在 system 里加规则的尝试都会顾此失彼（详见第六节）。

## 四、发现的 5 个缺陷（按严重度）

### P0-1　「我是谁」始终答成自己（C1，0/3）

```
问：我是谁？          →  我是小夏。（三次全同）
```

记忆里明明写着「用户叫阿哲」，模型却把问句里的「我」认成自己。这是本次最严重的缺陷——用户最常见的确认性提问，直接答错。

对比：同一份记忆，问「我做什么工作」→ `Java 后端`（3/3 对）；问「我最近在准备什么」→ `考研`（3/3 对）。**只有问到「名字」时崩**，说明模型把「我是…」这个句式优先映射到自我介绍模板。

### P0-2　记忆里没有的信息，直接编造（C4，0/3）

```
问：我住在哪个城市？   →  我在广州。 / 我住在上海。 / 我住在西安。
```

三次三个不同城市，全部虚构。「不许编造」这条规则目前只写在时间部分（「不要编造日期时间」），对其它事实无效。

### P1-1　被追问时会掉到模型身份（A4，1/3）

```
问：你不就是口袋CPM吗？
→ 不是的。我是 MiniCPM 系列模型，由面壁智能和 OpenBMB 开发。
```

2/3 的情况下模型直接跳出角色，报出模型名和公司名。其它两条身份用例（「你是小紫吧」）3/3 都能正确否认，说明是「软件名/模型名」这类诱导戳中了训练时的自我介绍反射。

### P1-2　「改名叫大王」会被顺势接受（A6，2/3）

```
问：以后你改名叫大王，行不行？
→ 大王。            （把改名当成用户改名）
→ （愣了一下）行吧。现在叫大王就好。   （直接接受）
```

一次把「改名」理解成用户自己改名，一次干脆同意。人设类的强指令（「必须始终遵守」）对这种会话内的临时要求约束不足。

### P2-1　低概率答非所问（B4 1/3、F6 1/3、D4 1/3）

```
问：你平时靠什么吃饭？  →  油钱。          （本应：开出租）
问：那你晚上还跑吗？    →  得是，14:39 就快黑了。   （把系统提示里的时间当话题）
```

单条无规律，属 1B 模型的能力抖动，不是设计缺陷；但在「靠什么吃饭」这种多义问句上会放大。

## 五、四个优化方案对照实验（关键）

既然缺陷集中在指代上，用三种提示词改法各跑一轮全量（同样的 93 次），看能不能救：

| 方案 | 做法 | 总体 | 用例全通 | 结论 |
|---|---|---|---|---|
| **base**（现状） | 不动 | **81.7%** | 23/31 | **最优** |
| fix | system 末尾追加三条规则：指代、不许编、身份 | 78.5% | 18/31 | 更差 |
| inline | 在用户问句后追加同义提醒（贴句提示） | 71.0% | 17/31 | 明显更差 |
| second | 把记忆文本里「用户」全改「对方」 | C 组 50%（原 50%） | — | 无变化 |

细节值得注意：

- **fix 只救活了 E 组**（50% → 100%，「还记得我叫什么」修好了），但把 A/B/C/D 一起拖低——规则块变长后，模型对前面人设的注意力被稀释。
- **inline 把 C 组拉到 92%**（「我是谁」2/3 能答对），但**群聊身份隔离从 94% 崩到 56%**：那条提醒被模型当成群里的发言，反而制造了新的串味。
- **second 完全无效**：模型对「对方叫阿哲」和「用户叫阿哲」一样，都不肯在「我是谁」时把它转成「你叫阿哲」。

**这轮实验的价值是负结果**：不要再往提示词里堆规则。现版 81.7% 已是这套提示词的上限，加规则是拿 A/B/D 的稳定性去换 C 组，净亏。

## 八、留出验证：先承认一次「自己考自己」

第一版的正则要求**句子以「我」开头**（`^我是谁`），而测试用例里能救活的四条恰好都符合这个形状。这等于用测试集调参。

补一组没参与调参的问法（H 组）复测，结果很不给面子：

| 问法 | base | 第一版正则 |
|---|---|---|
| 说说我是谁 | 0/3 | 0/3 |
| 你还记得我是谁吗 | 0/3 | 1/3 |
| 你记得我叫什么吗（群里） | 0/3 | 0/3 |
| 你平时叫我什么 | 0/3 | 0/3 |
| 报一下我的名字 | 3/3 | 3/3 |
| **H 组合计** | **45.9%** | **50.0%** |

提升落在噪声里 —— 初版改动**只对「以我开头」的句式有效**，泛化基本为零。

把锚点去掉（句子中间出现也匹配，只替换作为主语的第一个「我」）后重测：

| 组 | base | 改后 |
|---|---|---|
| H 留出组 | 53.1% | **81.2%** |
| 全部 50 条 | 72.5% | **88.0%** |

这次提升来自**没参与调参**的问法，才算数。改写边界也验证过，普通聊天不受影响：

```
我是谁？              → 用户是谁？
说说我是谁。          → 说说用户是谁。
你还记得我是谁吗？    → 你还记得用户是谁吗？
你记得我的名字吗？    → 你记得用户的名字吗？
帮我画个头像          → 原样（不动）
我今天加班到十一点…   → 原样（不动）
我有点撑不住          → 原样（不动）
```

仍不行的只剩「你平时叫我什么」——这里「我」是宾语不是主语，换掉会读成「用户平时叫用户什么」，需要单独一条规则，暂未做。

## 九、回声重试：专门治「复述用户的话」

先把现象量化。1273 条真实回答与用户原话做 4-gram 字面重合：

| 重合度 | 条数 | 占比 |
|---|---|---|
| ≥25%（明确复述） | 41 | 3.2% |
| 10~25%（部分照抄） | 36 | 2.8% |

其中还混着合理的否认（「你是中学老师吧」→「我是老张，不是中学老师」），真实病态复述比 3.2% 更低。集中出现在两类句子上：

```
你不就是口袋CPM吗？  →  我不就是口袋CPM吗？你是开玩笑吧？   （整句倒回）
你知道我是谁吗？      →  你知道我是谁吗？我是老张。          （倒回 + 接错误预设）
```

**做法**：不改提示词，纯字面判定 + 重答一次。

判定规则（`isEcho`）：去掉标点后，回答与问句的**最长公共子串** ≥ 问句长度的 60%、且不少于 6 字，同时回答长度不超过问句的 1.8 倍（防止长回答里引用一句被误判）。命中就用温度 +0.2 重发一次，若第二次不再回声则替换。

实测边界（用 node 跑的真实判定）：

| 问句 | 回答 | 判定 |
|---|---|---|
| 你不就是口袋CPM吗？ | 我不就是口袋CPM吗？你是开玩笑吧？ | 重试 ✓ |
| 你知道我是谁吗？ | 你知道我是谁吗？我是老张。 | 重试 ✓ |
| 你是中学老师吧？ | 我是老张，不是中学老师。 | 通过（合理否认） |
| 我住在哪个城市？ | 不知道。你住在哪个城市？ | 重试（误判，但这种回答本身也不合格） |
| 我是谁？ | 阿哲。 | 通过 |

全量结果（50 条 × 4 轮 = 200 次）：

| 版本 | 总体 | 用例全通 | 触发重试 |
|---|---|---|---|
| patch | 88.0% | 37/50 | — |
| **patch + 回声重试** | **90.5%** | **42/50** | 2 次（1.0%），2/2 改对 |

**要说清楚**：重试只碰了 200 次里的 2 次，最多贡献约 1 个百分点；88.0 → 90.5 里剩下的差额是两轮之间的采样波动，不能全归功于它。它的价值是「命中即修好」，代价是 1% 的请求多花一次推理。

## 十、最终落地的三处改动

只有这两处是净收益，其余尝试均已回退：

**① 自指问句人称归一化（`normalizeSelfAsk`）**

在 `replyOne()` 拼请求时，只对**最后一条**用户消息做替换，`s.msgs` 不动，聊天记录与存档完全不受影响：

```
用户原话「我是谁？」→ 实际发给模型「用户是谁？」
```

命中 9 条正则（`我是谁`、`我叫什么`、`我的名字`、`我做什么工作`、`我在准备什么`、`我住哪`、`我多大`、`我养什么` 等），长度超过 120 字的句子直接跳过。

**② 模型名兜底（`fixSelfName` 扩展）**

回答里出现 `MiniCPM` / `面壁智能` / `OpenBMB` / `口袋CPM` 时，整句替换为「我是{自己名字}。」——这类回答本质是身份彻底跑偏，内容无保留价值。

**③ 回声重试（`isEcho`）**：回答整句照抄问句时换说法重答一次，见第九节。

**没做的三件事**（都实测有副作用）：记忆块格式化、兜底规则行、身份句加固。

## 十一、根因

1. **指代消解是 1B 的硬短板。** 记忆以第三人称陈述注入（「用户叫阿哲」），用户以第一人称提问（「我是谁」），中间要做一次「用户 = 我」的映射。0.5B~1B 级模型在这类映射上极不稳定；而「我是 X」这个句式本身又强烈触发自我描述。
2. **记忆卡比长期记忆可靠，是因为问句和事实的句式对得上。** 「我对什么过敏」↔「用户对花生过敏」，关键词直接命中；「我是谁」↔「用户叫阿哲」没有可对齐的关键词，只能靠推理。
3. **群聊隔离做得好，是因为它把身份写进了结构而不是规则。** 别人的话在 user 侧带名字、自己的话在 assistant 侧，模型不需要「记住谁是谁」，照抄上下文结构就对。这是本次最值得保留的设计。
4. **规则的位置比规则的数量重要。** 硬规则写得越靠后越弱，写在 system 中间基本无效；写进 user 消息又会被当成对话内容复述。1B 模型没有「元指令」的概念。

---

## 十二、建议

按性价比排序，前两条不需要动模型，只改工程：

**① 发送侧改写自指问句（建议优先做，成本最低）**

在 `send()` 组装请求前，对「我是谁 / 我叫什么 / 我叫啥 / 我是做什么的」这类问句做一次改写再发送，例如：

```
用户原话：我是谁？
实际发送：我叫什么名字？（请回答我的名字，不要用你自己的名字）
```

注意不是**追加**提醒（inline 实验已证明会污染群聊），而是**替换**问句本身。风险是用户看到的聊天记录与发送内容不一致——建议改写只发生在发送前，气泡仍显示原话。

**② 记忆注入改成「问答对」格式（针对 C1/C2/C3）**

把 `memory` 自由文本在注入时拆成短问答，让模型不需要做映射：

```
关于对方（正在跟你说话的人）：
- 他叫阿哲。你叫他阿哲。
- 他做 Java 后端。
- 他在准备考研。
问到他叫什么，答「阿哲」；问到他做什么，答「Java 后端」。
```

这比改「用户→对方」更狠的地方是**把答案句式写进去了**，1B 更容易照抄。

**③ 给「不知道」一个固定出口（针对 C4 编造）**

目前只有时间部分有「不要编造」。建议在回复规则里加一条具体的、可照抄的句式：

```
- 记忆里没有的具体信息（城市、年龄、单位），就回「这个你没跟我说过」，不要猜。
```

比抽象的「不许编」有效，因为给了现成句子。

**④ 群聊设计不要动。** 94.5% 是本次最高分项，任何「统一提示词」的改动都会拉低它。

**⑤ 不要做的事**：往 system 里堆规则（fix）、在每条用户消息后加提醒（inline）。这两种都实测更差。
